# Как работать над WhoAmI

Мы работаем в [общем репозитории WhoAmI](https://github.com/Alona674/WhoAmI)
и отправляем готовые изменения прямо в ветку `main`. Каждый сам проверяет
свою работу перед отправкой. Создавать отдельные ветки и pull request
для этого порядка работы не нужно.

Git хранит историю изменений проекта на вашем компьютере. GitHub — сайт,
через который мы обмениваемся этими изменениями.

| Слово или команда | Что означает |
| --- | --- |
| Репозиторий | Папка проекта вместе с историей изменений |
| `main` | Общая ветка, в которой собирается работа команды |
| `origin` | Короткое имя нашего репозитория на GitHub |
| `clone` | Скачать проект вместе с его историей в первый раз |
| `pull` | Получить изменения команды с GitHub |
| `commit` | Сохранить изменения в локальную историю Git |
| `push` | Отправить сохранённые коммиты на GitHub |

**После `commit` работа остаётся на вашем компьютере. На сайте и у команды
она появится только после успешного `push`.**

Первые два раздела выполняются один раз. При каждой новой задаче проходите
шаги 3–6. Копируйте команды и нажимайте **Enter** после каждой строки.
Дождитесь завершения команды перед следующей. Если появилась ошибка,
сначала выполните указания из раздела в конце файла.

## 1. Подготовьте компьютер — один раз

1. Создайте аккаунт на [GitHub](https://github.com/), если его ещё нет.
   Передайте свой логин владельцу репозитория и примите приглашение
   в команду. Для отправки изменений нужен доступ на запись.
2. Установите [Git](https://git-scm.com/install/),
   [GitHub CLI](https://cli.github.com/) и Godot 4.6.
   GitHub CLI поможет войти в аккаунт из консоли.
3. Откройте консоль: **Git Bash** в Windows или **Терминал** в macOS/Linux.
   В Windows Git Bash устанавливается вместе с Git. Если консоль была
   открыта во время установки программ, закройте и откройте её заново.
4. Проверьте установку, выполняя команды по одной:

   ```bash
   git --version
   gh --version
   ```

   Обе команды должны вывести номер версии. Если видите `command not found`
   или «команда не найдена», вернитесь к установке соответствующей программы.

5. Укажите автора будущих коммитов. Замените имя и почту на свои, сохранив
   кавычки. Используйте почту, добавленную в ваш аккаунт GitHub:

   ```bash
   git config --global user.name "Ваше имя"
   git config --global user.email "you@example.com"
   ```

6. Войдите в GitHub. В **macOS/Linux** выполните:

   ```bash
   gh auth login --hostname github.com --git-protocol https --web
   ```

   В **Git Bash на Windows** выполните этот вариант:

   ```bash
   winpty gh auth login --hostname github.com --git-protocol https --web
   ```

   Достаточно одной команды для вашей системы. Вариант с `winpty` учитывает
   [особенности ввода в Git Bash](https://cli.github.com/manual/gh_help_mintty).
   Следуйте подсказкам: откройте предложенную страницу, введите одноразовый
   код из консоли и подтвердите вход своим аккаунтом. Если программа
   спрашивает, использовать ли этот аккаунт для Git, ответьте `Y`.

7. Подключите этот вход к Git и проверьте аккаунт:

   ```bash
   gh auth setup-git --hostname github.com
   gh auth status
   ```

   В результате должен быть указан ваш аккаунт на `github.com`.
   Подробности есть в официальных инструкциях по
   [входу](https://cli.github.com/manual/gh_auth_login) и
   [настройке Git](https://cli.github.com/manual/gh_auth_setup-git).

## 2. Скачайте проект — один раз

В той же консоли выполните команды по очереди:

```bash
mkdir -p ~/projects
cd ~/projects
git clone --branch main https://github.com/Alona674/WhoAmI.git
cd WhoAmI
git status
```

Они создадут папку `projects` в вашей домашней папке и скачают в неё
`WhoAmI`. Символ `~` обозначает домашнюю папку вашего пользователя.
В ответе последней команды должны быть `On branch main` и
`nothing to commit, working tree clean` — проект готов к работе.

Откройте в Godot файл `project.godot` именно из `projects/WhoAmI`.
Порядок импорта и управление описаны в [README.MD](README.MD).
Все дальнейшие изменения делайте в этой папке.

Повторно выполнять `clone` перед каждой работой не нужно. Дальше каждый
раз начинайте с шага 3.

## 3. Перед работой получите изменения команды

Сначала договоритесь в чате, кто какую комнату или объект меняет.
Особенно важно согласовать одновременную работу над одной сценой `.tscn`
или настройками `project.godot`.

Сохраните файлы и закройте Godot. Откройте консоль и перейдите в проект:

```bash
cd ~/projects/WhoAmI
git status
```

Должно быть написано `nothing to commit, working tree clean`.
Если перечислены изменённые или новые файлы с прошлого раза, сначала
проверьте и сохраните их по шагам 4–5. Затем вернитесь сюда.

Переключитесь на общую ветку и получите последние изменения:

```bash
git switch main
git pull --no-rebase --no-edit origin main
```

`Already up to date` означает, что у вас уже последняя версия.
При получении новых изменений Git выведет список обновлённых файлов.
Если появилось `CONFLICT`, перейдите к разделу об ошибках в конце файла.

## 4. Внесите изменения и проверьте игру

1. Откройте проект в Godot и выполните одну небольшую задачу.
2. Сохраните изменённые сцены и скрипты.
3. Нажмите **F5**, начните новую игру и проверьте свой сценарий.
4. Проверьте связанные действия: движение `A` / `D`, взаимодействие `E`,
   диалоги, двери в соседние комнаты и паузу через `Esc`.
5. Если меняли контейнер, проверьте сбор предметов двойным щелчком,
   кнопку «Забрать всё» и повторное открытие контейнера.
6. Проверьте, что в отладчике Godot не появились новые ошибки.

Если меняли только текст документации, проверьте текст и ссылки.
После проверки сохраните файлы и закройте Godot, прежде чем продолжать.

## 5. Сохраните результат в локальную историю

Посмотрите, какие файлы изменились:

```bash
git status
git --no-pager diff
```

В `status` слово `modified` означает изменённый файл, `deleted` — удалённый,
а `Untracked files` — новые файлы. В `diff` строки с `-` показывают старый
текст, с `+` — новый. Новые файлы до добавления в Git видны только в `status`.

Убедитесь, что все изменения относятся к вашей задаче. Затем подготовьте
их к коммиту и ещё раз проверьте список:

```bash
git add .
git --no-pager diff --cached --stat
```

`git add .` подготавливает все изменения в папке проекта, включая новые
файлы и удаления. Если в списке есть непонятные или случайные изменения,
сначала разберитесь с ними. Снять подготовку со всех файлов можно командой
`git restore --staged .` — сами файлы и ваши правки останутся на месте.

Когда список верен, создайте коммит. Замените текст в кавычках коротким
описанием того, что вы сделали. Например:

```bash
git commit -m "Добавил предметы в ванной"
```

Коммит — точка сохранения вашей работы. Следующий шаг отправит её команде.

## 6. Получите свежие изменения и отправьте свою работу

Пока вы работали, кто-то мог обновить проект. Сначала получите его изменения:

```bash
git pull --no-rebase --no-edit origin main
```

Команда объединяет изменения команды с вашими коммитами. При необходимости
Git создаст дополнительный коммит объединения; `--no-edit` позволяет принять
его готовое описание без открытия текстового редактора.
Подробнее — в [документации Git](https://git-scm.com/docs/git-pull).

Если появились конфликты, остановитесь и выполните действия из раздела ниже.
Если обновились игровые файлы, снова запустите проект через **F5** и проверьте
свой сценарий. Если пришлось что-то исправить, повторите шаги 5–6.

После успешной проверки закройте Godot и отправьте коммиты:

```bash
git push origin main
git status
```

После успешной отправки `status` должен сообщить, что ветка актуальна
относительно `origin/main` и нет несохранённых в Git изменений.

Откройте [историю коммитов на сайте](https://github.com/Alona674/WhoAmI/commits/main/)
и найдите своё описание. Проверьте изменённый файл на сайте, затем напишите
в чат команды, что готово и что вы проверили. Остальные получат вашу работу
командой `pull` из шага 3.

## Если что-то пошло не так

### `not a git repository`

Консоль открыта вне папки проекта. Выполните:

```bash
cd ~/projects/WhoAmI
git status
```

### `Permission denied`, `403` или ошибка входа

Проверьте аккаунт командой `gh auth status`. Если входа нет, повторите
вход из шага 1. Если аккаунт верный, попросите владельца репозитория
проверить доступ на запись и убедитесь, что приняли приглашение.

### `push` отклонён: `rejected`, `fetch first` или `non-fast-forward`

Кто-то отправил изменения раньше вас. Повторите шаг 6: `pull`, проверка
проекта, затем `push`. Не используйте `git push --force`: он может убрать
работу других участников из общей истории.

### `Your local changes would be overwritten`

У вас есть правки, которые ещё не сохранены коммитом. Выполните шаги 4–5,
затем повторите шаг 6. Не удаляйте файлы ради успешного обновления.

### При `pull` появилось `CONFLICT`

Git не смог автоматически объединить правки одного файла. Не отправляйте
проект в таком состоянии. Отмените начатое объединение:

```bash
git merge --abort
```

Ваши коммиты из шага 5 останутся на месте. Отправьте в чат команды сообщение
об ошибке и названия конфликтующих файлов. Договоритесь с тем, кто менял
эти файлы, как объединить обе правки. До решения конфликта не повторяйте
`push` и не выбирайте целиком одну версию файла наугад.

## Несколько правил для файлов Godot

- Сцены находятся в `scenes/`, скрипты — в `scripts/`, изображения — в `art/`.
- Сохраняйте рядом с новыми скриптами и шейдерами файлы `.gd.uid`
  и `.gdshader.uid`: это ссылки, по которым Godot находит ресурсы.
- Перемещайте и переименовывайте ресурсы через панель файлов Godot,
  чтобы редактор обновил ссылки на них.
- Учитывайте регистр: `scenes/ui/` и `scripts/UI/` — разные пути.
- Папка `.godot/` исключена из Git через `.gitignore`. Не добавляйте её
  принудительно.
- Не заменяйте весь проект старым ZIP-архивом. Работайте в скачанной
  через `clone` папке и получайте обновления через `pull`.
